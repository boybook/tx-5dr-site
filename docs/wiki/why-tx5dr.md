# 设计目标与边界

TX-5DR 面向的不只是一台电脑上的单机数字模式操作。电台可以位于机房、楼顶或野外站，操作者可以使用另一台电脑、平板或手机，服务端仍需继续管理电台、音频和时序。

## 远程操作是基本形态

界面与物理电台之间没有必然的本机关系。Web 前端只依赖服务端接口，因而桌面窗口、局域网浏览器和经 HTTPS 公开的远程浏览器共用同一套界面。这个边界消除了传统远程桌面的图像编码、分辨率、音频重定向和会话锁屏问题。

## 服务端拥有物理资源

电台连接、声卡、PTT、解码工作队列和持久化数据由服务端统一持有。客户端断线后，这些资源不跟随界面销毁；客户端重连时重新取得快照和增量事件。

这个所有权也是 RF 安全的基础：

- 底层电台 I/O 经由受控的串行队列。
- PTT、切频和切模式不由多个浏览器直接竞争。
- 自动化插件提交意图或提议，Host 仍负责权限、仲裁和最终执行。
- 身份、时隙或电台状态不足时，发射决策保持关闭。

## 硬件差异收敛在适配层

Hamlib、ICOM WLAN 和 TCI 的建链方式、可控参数、音频和频谱能力并不一致。上层不以电台型号编写一系列分支，而是从当前连接取得能力快照，再把频率、模式、PTT、数值表和控件统一投影给 Web 界面。

## 状态与实时数据使用不同传输

配置和命令需要可确认的请求结果，适合 REST。电台状态、解码结果和插件事件需要服务端持续推送，适合 WebSocket。实时音频对过期帧没有兴趣，适合无序、不可靠的 WebRTC DataChannel/UDP，并保留 WebSocket 回退。

## 运行形态共用同一个业务核心

- 桌面版由 Electron 启动本地服务端并打开桌面窗口。
- Linux 服务器和 Docker 直接运行 Server 与 Web 入口。
- Android 应用在私有 Debian PRoot 中运行完整 Server/Web 运行时，并桥接 Android 音频和 USB 串口。它不是仅连接其他 TX-5DR 服务器的移动客户端。

## 功能成熟度

FT8 和语音属于正式功能。FT4、CW、SSTV 和 FAX 仍处于实验阶段，其中 FAX 在 TX-5DR 中是只接收模式。实验功能可以具有完整的代码和界面，但不与正式功能共享相同的稳定性承诺。

## 稳定边界

TX-5DR 把稳定性承诺放在明确的公共界面上：插件 API、公开 npm 库、标准 rigctld 协议和持久化数据格式。服务端内部类、未版本化 REST 路由和主 WebSocket 消息可随官方客户端同步演进。
