# FT8 与 FT4

::: tip 功能状态
**FT8 是正式功能。FT4 是实验功能。** 两者共用数字工作区和主要通联机制，但 FT4 的时序、解码策略和部分高级行为仍可能调整。重要通联和比赛操作请优先使用经过自己验证的版本与配置。
:::

TX-5DR 可以持续解码 FT8、按标准报文完成 QSO、管理多个待通联目标、运行自动起呼规则，并在服务器上保存日志。电台可以长期留在站点旁，操作员通过网页完成通联，不需要远程桌面。

## 能做什么

- 解码 FT8，以及实验性的 FT4。
- 查看全频段解码、与当前操作员有关的消息、瀑布和电台数值表。
- 手动选择目标、发起 CQ，并自动推进 TX1 到 TX6。
- 使用“辅助队列”依次处理多个手选目标或直接来呼。
- 使用守候呼号、守候网格、守候新 DXCC/新呼号、定时 CQ 等自动化插件。
- 使用 WW Digi 专用通联、候选选择、实时计分和独立比赛日志。
- 识别 Fox/Hound 复合 RR73，并完成 Hound 一侧的标准应答。
- 完成后自动写入当前操作员日志，并按已配置的 Provider 同步。

## 发射前检查

第一次只开接收，不要直接打开操作员 PTT。

1. Profile 已连接，接收输入和发射输出指向正确设备。
2. 操作员呼号和 Grid 正确；FT8 报文只会发送 Grid 的前 4 位。
3. 电台在正确的 USB 或 DATA 模式，滤波和数据输入设置适合数字模式。
4. UTC 校时正常。FT8 每周期 15 秒，FT4 每周期 7.5 秒，明显时差会导致全频段无法解码。
5. 频率符合当地频率规划；预设是常用活动频率，不代表在任何地区、任何时间都可发射。
6. 天线、功率、SWR 和散热适合连续占空比发射。
7. 先用低功率检查 ALC。ALC 过高时降低 TX-5DR 发射总增益或电台数据输入增益。

## 第一次收到 FT8

1. 在底部模式下拉框选择 **FT8**。
2. 从频率下拉框选择当前波段的 FT8 预设，例如 20 米 `14.074 MHz`。
3. 打开底部 **引擎**。
4. 等待一个完整周期。左侧应开始出现 UTC、dB、DT、音频频率和报文。
5. 查看瀑布是否有 0 到 3000 Hz 范围内的信号，并确认接收数值表有变化。

成功时会同时看到：

- 左侧“全部解码”持续增加报文。
- 解码按接收周期分组，并用背景区分奇偶周期。
- 报文中的呼号、位置、新 DXCC/新网格等信息按当前显示设置标记。
- 选择一个操作员后，与自己或目标有关的报文出现在右侧上方。

表格中的 **频率** 是音频偏移，不是电台拨盘频率；实际 RF 大致为拨盘频率加该偏移。

### 解码列表的常用操作

- 双击对方报文：把该呼号交给当前操作员。标准通联会准备呼叫；队列机制会把目标加入队列。
- 悬停报文：在支持的频谱上指出对应音频位置。
- 点击 dB 或距离排序：只改变当前周期内的显示顺序，再点一次恢复原顺序。
- 呼号位置/旗帜：查看台站与 Grid 信息。
- 清空按钮：可分别清空左侧解码、右侧相关消息或全部显示；不会删除日志。

## 完成第一次标准 QSO

### 1. 选中操作员和通联机制

点击右侧操作员卡片，使它成为当前操作员。顶部 **通联机制** 中选择 **标准通联**。

单操作员第一次使用时，建议关闭自动回应和自动恢复 CQ，只保留人工选择目标。这样每次发射都容易判断来源。

### 2. 选择发射周期

观察目标最近一条报文所在周期，然后让自己在相反周期发射。

- FT8 的 **00/30** 表示偶数周期发射。
- FT8 的 **15/45** 表示奇数周期发射。
- FT4 使用“偶数周期/奇数周期”显示，周期长度为 7.5 秒。

点击周期按钮即可切换。双击报文本身不会替你更改标准通联的发射周期，因此发射前必须再看一眼。

### 3. 选择目标和音频位置

1. 在左侧双击目标的 CQ。
2. 确认操作员卡片的 **目标** 已变为对方呼号。
3. 确认当前消息为 TX1，报告和 Grid 正确。
4. 在 **频率** 输入框填写 1 到 3000 Hz 的发射音频偏移，或点击魔杖自动寻找较空闲位置。
5. 也可以在支持交互的瀑布上拖动当前操作员的发射标记或右键选择位置。

不要把发射标记压在正在进行的 QSO 上。自动择频依据最近接收周期估算空闲位置，仍需操作员查看瀑布确认。

### 4. 开始并观察自动推进

打开操作员卡片右上角的 **PTT** 开关。下一个属于该操作员的发射周期到来时，卡片会显示将要发送的报文；物理发射时页面出现红色边框。

标准通联会根据对方回复自动从 TX1 推进到报告、确认和 73。每轮都检查：

- 当前目标仍是预期呼号。
- 发射周期和音频偏移没有被其他客户端改变。
- Power、SWR、ALC 正常。
- 对方报文出现在右侧相关消息中。

完成后，操作员会按设置停止，或回到 TX6 继续 CQ。点击卡片的 **日志** 可查看刚写入的 QSO。

## 发起 CQ

1. 在操作员卡片把状态重置到 **TX6**。
2. 展开详情，确认 TX6 内容。默认是 `CQ 自己呼号 Grid`，也可编辑为可编码的 CQ 文本。
3. 选择奇偶周期和发射音频位置。
4. 打开操作员 PTT。
5. 收到直接回复后，标准通联会选择对方并进入报告流程。

只想呼叫有限轮次时，不要离开页面不管。标准通联的超时设置控制单个 QSO 的等待，不等同于总发射时长限制。

## TX1 到 TX6

| 状态 | 常见报文 | 用途 |
| --- | --- | --- |
| TX1 | `对方 自己 Grid` | 主动呼叫并发送 Grid |
| TX2 | `对方 自己 -nn` | 发送信号报告 |
| TX3 | `对方 自己 R-nn` | 确认收到对方报告 |
| TX4 | `对方 自己 RR73` | 确认并结束报告交换 |
| TX5 | `对方 自己 73` | 最终致意或补发 73 |
| TX6 | `CQ 自己 Grid` | 发起 CQ 或停发待机状态 |

点击当前消息下拉框可以人工切换状态；展开详情后可查看或编辑各条报文。正常 QSO 应让通联机制自动推进。人工切到错误状态、修改 TX1 到 TX5，可能造成日志报告与实际交换不一致。

**跳过 TX1** 会在主动呼叫 CQ 台时从 TX2 开始，节省一轮但不发送自己的 Grid。只在了解对方工作方式时使用。

## 标准通联的自动选项

顶部 **通联机制** 面板提供这些常用开关：

- **自动回应他人 CQ**：操作员在 TX6 守听时，从符合条件的 CQ 中选台并呼叫；不会主动替你发起 CQ。
- **停发待机时回应直呼**：PTT 已关闭但有人直接呼叫本台时，允许重新启动回应。
- **失败后继续 CQ**：当前 QSO 超时后回 TX6 继续发 CQ；关闭时停发。
- **完成 QSO 后继续 CQ**：记录成功后继续发 CQ；关闭时停发并守听。
- **已通联直呼也回应**：对方直接叫你时允许重复 QSO；他人 CQ 仍受已通联过滤。
- **按频段判断已通联**：只把当前波段做过的呼号视为 worked。
- **自动选台偏好**：可优先新 DXCC、新呼号，或综合新网格和信号条件。
- **无回应超时 / TX1 最多轮数**：限制卡在某一步或连续首呼的次数。

这些设置按操作员保存。多操作员时逐一确认，不能假设一个人的开关会应用到其他人。

*标准通联选项控制当前操作员的自动回应；守候插件负责按 DXCC、Grid 或呼号发现目标。*

## 辅助队列

辅助队列适合“我来选目标，系统依次完成”的操作方式。

### 开启

1. 管理员在 **设置 > 插件** 启用 **辅助队列**。
2. 选中操作员，在顶部 **通联机制** 中把流程切换为 **辅助队列**。
3. 设置同时通联数。默认 1，当前上限 3；操作员自身的同时通联上限还会进一步限制它。

### 使用

1. 双击左侧报文把呼号加入队列。空闲时会立即开始处理。
2. 可靠的直接来呼也会自动进入队列。
3. 拖动尚未开始的条目可调整顺序。
4. 使用条目上的 **重试**、**移除/中断并移出**，或队列顶部的 **清空**。
5. 查看“通联中、暂停、未回应、需确认”等状态，并留意条目最后一次出现的周期。

队列仍使用标准 TX1 到 TX5 报文，不是竞赛协议。标准 FT8/FT4 活动频率上，系统会限制同呼号的并行发射并可能改为逐台处理；不要把“三路”理解为任何频率都允许同时发送三条信号。

## 自动起呼插件

TX-5DR 可在“通联机制”面板中叠加已启用的自动化：

| 自动化 | 适合场景 |
| --- | --- |
| 守候呼号 | DX、朋友台、远征台或 sked 出现时自动呼叫 |
| 守候网格 | 指定 Grid 或区域出现时自动呼叫 |
| 守候新类型 | 追逐日志中尚未完成的新 DXCC、新 Grid 或新呼号 |
| 定时自动起呼 | 按本地时间或固定间隔启动 CQ |
| 自动起呼自动择频 | 自动起呼被接受后先选较空闲的音频位置 |
| 定时自动切换频率 | 按时间表或轮换列表改变整台电台频率 |

启用后，操作员 PTT 附近会显示自动起呼状态。悬停或长按可查看来源，并可 **全部暂停自动起呼**。暂停只阻止这些插件接管发射，不会替你关闭已经手动打开的操作员 PTT。

自动起呼会真实控制电台。先在有人看守、低功率条件下验证匹配规则、重复台过滤、频率权限和停止方式，再考虑长时间运行。

## WW Digi

WW Digi 是独立的竞赛通联机制，不是给普通 FT8 QSO 加一层计分。

### 使用前

1. 管理员启用 **WW Digi** 插件。
2. 把当前操作员的通联机制切换为 **WW Digi**。
3. 打开操作员卡片中的 **WW Digi 日志**。
4. 选择届次，填写并确认参赛呼号、Grid、LOCATION、功率、操作员和发射机类别。
5. 确认当前在 160、80、40、20、15 或 10 米允许波段，并处于对应比赛时段。

设置未确认、比赛日志异常、波段不允许或比赛时段不符时，界面保持接收但禁止发射。不要用人工切换 TX 状态绕过提示。

### 通联和候选

- 列表为空时打开操作员 PTT，会按设置重复 CQ。
- 多人回应时，候选可按最早解码、最远距离、最高或最低 SNR 排序。
- 最多同时处理 3 路，其余保留等待；操作员仍需对候选执行 **呼叫** 或其他提示动作。
- 重复台、缺 Grid、反复 RR73、恢复观察等情况会显示明确动作，不会一律自动发射。
- 比赛日志提供实时预估分、需处理记录、ADIF 导入，以及 ADIF/Cabrillo 下载。

WW Digi QSO 保存在该比赛自己的日志中，不进入普通主日志，也不会自动送往普通日志同步 Provider。赛后应在 WW Digi 日志页完成审核和导出。

比赛时间外的 **临时演练** 只应在双方约定的非标准频率使用。演练日志会在关闭演练、切频或退出后删除，不可作为正式比赛日志。

## Fox/Hound 边界

标准通联和辅助队列能够识别 Fox 的复合 RR73：当其中邀请了自己的呼号时，可进入 Hound 的 R-report 流程；当自己的呼号被列为已完成时，可结束并记录 QSO。

当前界面没有完整的 DXpedition Fox 发射控制台，也不会替 Fox 同时编排多路下行。这里的兼容能力是 **Hound 一侧接收和应答**，不是“可作为 Fox 台运行”。部分解码只剩哈希或无法可靠识别发送者时，不应据此自动起呼。

## 日志

标准通联、辅助队列在协议达到完成状态后自动写入当前操作员日志。记录包含呼号、时间、频率、模式、双方报告、Grid 和报文历史。

1. 点击操作员卡片的 **日志**。
2. 找到刚完成的 QSO，核对频率、FT8/FT4、报告和时间。
3. 如使用外部同步，检查 Provider 状态；“本地已记录”不等于外部服务已经接收。

WW Digi 使用独立比赛日志，不能在普通日志页寻找或修改其计分事实。

## 停止发射

1. 关闭对应操作员的 PTT，阻止后续周期继续排程。
2. 如果当前帧已经在空中，打开 PTT 浮层并点 **立即停止发射**。
3. 暂停所有自动起呼插件，防止操作员稍后又被自动启动。
4. 确认页面红框消失、电台回 RX、Power 和 ALC 回落。
5. 还要停解码时，再关闭底部 **引擎**。

不要先关闭网页。数字操作员运行在服务端，关掉浏览器不构成可靠的停发动作。

## FT4 的实验差异

- 周期为 7.5 秒，操作和决策窗口比 FT8 更紧。
- 使用独立的 FT4 频率预设；切换 FT8/FT4 会重置当前数字通联。
- 奇偶周期仍存在，但界面使用“偶数/奇数”而非 FT8 的 00/30、15/45。
- 标准通联和辅助队列复用同一套主要流程，但应先在有人值守时验证电台切换、解码和日志。
- WW Digi 可处理 FT4，但 FT4 本身仍是实验功能；比赛前必须用当前版本完成实际链路验证。

## 常见问题

### 瀑布有信号但没有解码

- 检查 UTC 误差和时区无关，关键是系统时钟本身准确。
- 确认选择了正确模式和活动频率。
- 检查音频输入、采样率、AF/IF 选择和电台 DATA 输出。
- 关闭电台静噪，避免弱数字信号被切断。
- 降低过高的接收电平；满幅削波不会带来更多解码。

### 双击后没有发射

- 确认双击的是可识别的对方呼号，不是自己的呼号或不完整占位符。
- 确认当前选中了正确操作员，并且有操作权限。
- 标准通联要再打开操作员 PTT；队列模式则查看条目是否暂停、需确认或周期不匹配。
- WW Digi 查看参赛设置、比赛时段、波段和日志健康提示。

### 一直呼叫但没有回应

- 检查自己的发射周期是否与对方相反。
- 确认实际 RF 和音频偏移没有落在通带边缘。
- 查看 Power、SWR、ALC；有音频不代表已经有效上射频。
- 低/高音频偏移导致部分电台功率下降时，可开启 **虚拟频差**。
- 检查是否误开 Split、XIT、RIT 或错误 DATA 输入源。

### 已完成但外部日志没有记录

先在 TX-5DR 本地日志确认。若本地存在而外部没有，检查日志 Provider；若本地也没有，保留相关报文和时间再排障。WW Digi 记录只会出现在它自己的比赛日志中。
