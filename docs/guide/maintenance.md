# 日常维护

长期运行的远程站需要定期更新、备份和检查健康状态。所有维护操作都应避开发射窗口，并确保有人能在异常时停止电台。

## 更新

| 运行形态 | 推荐更新方式 |
| --- | --- |
| 桌面版 | 在“设置 > 关于”检查更新；不支持自动安装的包会转到官网下载 |
| Linux 服务器 | `tx5dr status` 确认健康后执行 `tx5dr update` |
| Docker | `docker compose pull` 后执行 `docker compose up -d` |
| Android | 在 Android 状态页检查并安装 TX-5DR runtime 更新；APK 更新与 runtime 更新是两件事 |

更新前：

1. 停止所有操作员发射和语音 PTT。
2. 记录当前版本、Profile 和异常现象。
3. 导出重要日志本，并备份数据目录。
4. 确认远程站有恢复访问的方法。

更新后至少检查 Web 登录、电台连接、RX 音频、解码和 PTT 测试。实验功能还应检查相关历史数据能否打开。

## 备份什么

完整备份应包含：

- Profile、操作员、用户和系统设置
- 日志本及恢复文件
- 插件目录和插件数据目录
- 自定义证书
- SSTV/FAX 历史图片等实验功能数据
- 诊断所需但不含敏感凭据的运行日志

Docker 应保留整个 `./data` 映射目录，不要只挑几个子目录。Linux 服务器应备份安装命令显示的实际数据目录。桌面版可通过界面中的“打开目录”入口确认运行路径。

Android 数据位于应用私有空间。卸载应用或清除应用数据前，至少先导出日志和可下载的图片记录；不要假定普通文件管理器能恢复 runtime 数据。

## 查看服务器健康

主界面右上角的服务器健康入口会显示：

- CPU 和内存
- 事件循环延迟
- 解码工作线程、队列和并行能力
- 近期采样时间和异常状态

短时 CPU 升高不一定是故障，FT8 和实验性 FT4 的解码窗口会产生周期性负载。持续满载、解码队列增长或工作线程错误才需要进一步查看日志。

## 日志和错误历史

- 电台控制区可以查看电台错误历史
- **设置 > 插件** 提供插件运行日志
- **系统设置** 可以调整运行日志级别并打开日志目录
- 启动阶段异常可从启动状态面板打开日志

日常保持 `info` 或默认日志级别。只有在复现问题时临时使用 `debug`，完成后恢复，避免磁盘快速增长和日志包含过多运行细节。

## 提交诊断

进入 **设置 > 帮助改进**，可以选择时间范围并上传诊断日志。上传前检查页面显示的覆盖范围和来源。

诊断日志不应包含你主动粘贴的 API Key、密码或私人通联内容。提交后保留反馈 ID、错误发生时间、运行形态、版本和复现步骤，便于管理员对应日志。

## CPU Profile

管理员可以在性能诊断中采集服务端 CPU Profile。它适合定位持续高 CPU 或卡顿，不是普通错误日志的替代品。

- 只在能稳定复现性能问题时开启
- 覆盖一个足够短、可描述的时间窗口
- 通过正常重启或停止让文件完整写出
- 不要在比赛或无人值守发射期间做性能实验

## 定期检查清单

- 能从备用设备登录并立即停止发射
- UTC 时钟正常同步
- 电台和音频设备没有被系统重命名或断开
- 数据目录、日志和图片没有耗尽磁盘
- 管理员和操作员令牌仍符合当前人员权限
- 公网允许地址、证书和反向代理仍与实际入口一致
- 最近一次备份可以找到并读取
