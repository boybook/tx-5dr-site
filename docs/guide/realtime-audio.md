# 远程监听与语音链路

TX-5DR 自己提供电台音频的远程传输，不需要依赖远程桌面的音频重定向。浏览器可以监听电台；语音模式下，也可以把浏览器麦克风送到电台并控制 PTT。

大多数本机和局域网场景保持 **自动** 即可。只有公网、FRP、严格防火墙或音频断续时，才需要调整传输策略和端口。

## 两个方向

### 监听

电台或接收源的音频从 TX-5DR 运行主机传到浏览器。它用于：

- 远程收听语音
- 检查 FT8 或实验性 FT4 的接收音频
- 试听 OpenWebRX
- 观察延迟、缓冲和丢包

### 语音发射

浏览器麦克风送到运行主机，再由选中的电台音频输出发射。它需要：

- 操作员和语音发射权限
- 浏览器麦克风权限
- HTTPS 或 `localhost`
- 正确的发射音频输出和 PTT

## 第一次开启监听

1. 确认电台 Profile 的输入设备正确。
2. 在底部电台控制区点击 **开启监听**。
3. 允许浏览器播放音频；某些浏览器需要先点击页面。
4. 调整浏览器监听音量，不要误调电台 AF 增益。
5. 打开音频状态，确认传输、编解码和播放引擎已建立。

如果当前 Profile 使用 ICOM IF 输入，普通音频监听可能会被禁用。IF 是供频谱/解调用的基带，不是直接收听的语音音频。

## 第一次远程语音 PTT

1. 切到 **语音** 模式并选择正确频率和电台调制模式。
2. 确认浏览器地址使用 HTTPS 或 `localhost`。
3. 在系统提示时允许麦克风。
4. 查看输入电平，确认选择的是预期麦克风。
5. 低功率短按 PTT，检查电台是否发射、音频是否送达。
6. 松开 PTT 后确认电台立即回到接收。

公网测试前先在运行主机或同一 LAN 完成这组检查。这样可以把电台/PTT 问题和公网音频问题分开。

## 自动模式怎么工作

**设置 > 系统设置 > 实时音频 > 自动优选** 会先尝试低延迟 RTC；如果浏览器、运行环境或 UDP 无法建立，再回退到兼容 WS 方式。

你只需要根据状态判断：

- 显示 **低延迟 RTC**：当前会话使用 UDP DataChannel
- 显示 **兼容 WS**：当前会话通过现有网页 TCP 连接传输
- 自动回退提示：低延迟连接失败，但兼容方式仍可用

兼容方式是受支持的正常方案，不是必须修复的错误。只要音频质量和延迟满足当前操作，就可以继续使用。

## 不同网络怎么选

| 场景 | 建议 |
| --- | --- |
| 桌面应用窗口或本机浏览器 | 保持自动，无需额外端口 |
| 同一局域网 | 保持自动，确认主机防火墙允许 UDP `50110` |
| Android 内置 WebView | 优先使用 Android 原生音频路由，保持自动 |
| 通过 VPN 访问远程站 | 先保持自动；VPN 能转发 UDP 时通常不需公网候选 |
| FRP / 静态 NAT | 映射一个 UDP 端口并填写外部 UDP 地址 |
| 只有 HTTP/HTTPS 反向代理 | 使用自动回退，或直接选择兼容模式 |

## FRP 或静态 NAT

低延迟媒体需要一个可从浏览器到达的 UDP 端口。默认拓扑：

```text
公网 UDP 端口 -> TX-5DR 主机 UDP 50110
```

配置步骤：

1. 在路由器、云安全组或 FRP 中转发 UDP。
2. 进入 **设置 > 系统设置 > 实时音频**。
3. 填写浏览器实际能够访问的外部主机名/IP 和 UDP 端口。
4. 保存后断开并重新建立监听或语音会话。
5. 在音频状态中确认当前传输方式。

只保存设置不会重建已经存在的会话。

## 端口参考

| 端口 | 协议 | 用途 |
| --- | --- | --- |
| `8076` | TCP | 默认 HTTP Web UI |
| `8443` | TCP | Linux/Docker 默认 HTTPS Web UI |
| `50110` | UDP | 默认低延迟音频媒体 |

端口可以被部署配置修改，应以当前系统设置、`tx5dr status` 或 Compose 文件为准。

## HTTPS 为什么重要

浏览器通常只在安全上下文允许麦克风和完整音频能力。远程语音应使用受信任的 HTTPS：

- Linux/Docker 的自签名证书可用于初次 LAN 测试，但每台客户端都要确认信任
- 公网长期使用应配置正式证书或由可信反向代理终止 HTTPS
- HTTP 页面即使能控制电台，也可能无法获得麦克风或低延迟浏览器音频能力

## 音频断续和延迟

先保持编码与缓冲为自动。出现破音或间断时：

1. 查看欠载、抖动、播放缓冲和当前传输方式。
2. 临时切到兼容 WS，判断是否为 UDP 连接问题。
3. 增大监听或发射稳定性缓冲。
4. 检查 Wi-Fi 信号、VPN、FRP 和浏览器后台节流。
5. Android 检查实际音频路由是否仍为目标 USB/有线设备。

缓冲越大通常越稳定，但监听和 PTT 端到端延迟也会增加。不要只追求最低数值。

## 页面能打开但音频失败

- 确认使用 HTTPS 或 `localhost`
- 检查浏览器的麦克风和自动播放权限
- 检查运行主机能实际打开 Profile 中的音频设备
- 公网低延迟连接确认 UDP 而不只是 TCP 已转发
- 外部 UDP 地址应填写客户端能到达的地址，不是容器内部地址
- 重新建立会话，使新配置生效
- 使用兼容 WS 验证是否能先恢复功能

## 旧版本迁移

当前版本不再使用 LiveKit，也不需要 `/livekit`、LiveKit token、`7881/tcp` 或旧的媒体端口范围。旧部署残留的 LiveKit 配置只与升级清理有关，新用户不需要配置。

更广泛的公网权限和多人设置见 [操作员、用户与远程访问](./operators-remote)。
