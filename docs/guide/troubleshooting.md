# 按现象排障

先停止不受控的发射，再从“浏览器访问、电台连接、音频、时钟、模式、操作员”这条链路逐层检查。不要同时修改多个高级参数，否则很难判断是哪一步恢复了功能。

## 页面打不开

1. 在运行主机确认 TX-5DR 已启动。
2. Linux 服务器执行 `tx5dr status`；Docker 执行 `docker compose ps`。
3. 确认使用的是页面实际显示的地址和端口。
4. LAN 客户端检查主机防火墙和同网段连接。
5. 公网客户端检查反向代理、允许地址和 Origin 拒绝提示。
6. Android 点击刷新 LAN 地址，并确认 runtime 和 Web 状态都健康。

## 能打开页面但无法登录

- 区分管理员令牌、普通用户令牌和用户名密码
- 让管理员确认用户未被撤销或过期
- 操作员用户还需要被分配至少一个操作员
- Electron 自动登录使用短时授权，不应把地址栏里的临时信息当作永久令牌

## 电台连接测试失败

1. 确认电台开机，CAT 已启用。
2. 关闭 WSJT-X、JTDX、FLDIGI 等可能直接占用串口的软件。
3. 检查连接类型、机型、串口或网络地址。
4. Linux/Docker 检查串口权限和设备映射。
5. Android 确认已经授予 USB 权限，并使用桥接后显示的串口路径。
6. ICOM WLAN 或 TCI 检查同网段、登录信息、端口和服务开关。

连接成功但部分控制项缺失，不代表连接失败。扩展能力会按当前电台实际报告动态显示。

## PTT 测试失败

- 确认选择 CAT、VOX、DTR 或 RTS 的方式与实际接线一致
- DTR/RTS 使用独立接口时检查 PTT 串口
- VOX 不执行软件 PTT 测试，应改用低音量音频检查
- 网络连接检查远端 rigctld 是否允许 PTT 写入
- 测试失败后确认电台已经回到接收状态

## 没有瀑布图或 FT8 解码

1. 确认引擎已启动，模式是 FT8 或 FT4。
2. 确认输入设备是电台 RX 音频，不是电脑麦克风。
3. 检查声卡没有被其他程序独占。
4. 确认电台模式为 USB 或 USB-DATA，接收滤波足够宽，静噪关闭。
5. 检查瀑布图是否有信号；完全没有能量通常是音频链路问题。
6. 检查 UTC 时钟。能看到信号但长期无法解码时，时钟偏差是优先检查项。
7. OpenWebRX 接收时确认远端 Profile 覆盖当前频率。

## 有解码但双击后没有发射

- 确认已选择有控制权限的操作员
- 检查该操作员的通联机制已启用并完成设置
- 查看自动起呼是否被暂停
- 检查目标是否被过滤插件排除、已被其他操作员占用或违反重复通联设置
- 确认发射周期和目标消息仍然有效
- 查看操作员卡片和插件日志给出的拒绝原因

## 发射功率很低或 ALC 过高

1. 检查发射音频输出设备和声道。
2. 确认电台处于适合数字模式的 USB-DATA/USB 模式。
3. 从低总增益开始逐步增加。
4. ALC 过高时立即降低增益，不要靠降低 RF Power 掩盖音频过驱。
5. 音频频率过高或过低导致功率衰减时，可评估 FT8/FT4 的 **虚拟频差**。
6. 检查电台功率控制、天调状态和 SWR。

## 数值表或电台控制项没有出现

TX-5DR 只显示当前连接报告支持的项目：

- 接收时 Level 与发射时 Power 会共用位置
- SWR 和 ALC 通常只在 PTT 期间有有效值
- 某些功能只在特定电台模式下可用
- “不支持”和“当前忙碌/不可用”是不同状态

重新连接或点击电台控制面板中的刷新能力后仍没有出现，通常表示当前 backend 没有报告该能力。详见 [电台控制与数值表](./radio-controls)。

## 远程页面可用，但监听或麦克风失败

- 浏览器麦克风需要 HTTPS 或 `localhost`
- 检查浏览器站点权限和系统麦克风权限
- 先保持实时音频策略为 **自动**
- 公网低延迟连接检查 UDP 映射和外部 UDP 地址
- UDP 无法提供时，切到兼容模式验证 TCP 连接
- Android 检查原生音频路由是否显示“使用中”，不要接受静默回退到手机内置麦克风

详见 [远程监听与语音链路](./realtime-audio)。

## 插件已启用但没有效果

1. 区分全局启用与操作员分配。
2. 检查插件需要的是全局设置还是操作员设置。
3. 查看插件运行日志。
4. 暂停其他过滤或自动起呼插件，排除组合影响。
5. 确认市场插件支持当前 Host 版本。

## 日志本异常

- 先停止同步和发射
- 使用日志页的健康与恢复入口，不要直接覆盖文件
- 导出仍可读取的 ADIF
- 恢复后抽查最近 QSO、操作员和同步状态

## 仍然无法定位

记录以下信息后再提交诊断：

- 问题发生的本地时间和 UTC 时间
- TX-5DR 版本与 commit
- 桌面、Linux、Docker 或 Android
- 电台型号、连接方式、音频设备和 PTT 方法
- 最短复现步骤和界面错误文字
- 是否正在发射，以及是否能安全停止

然后通过 **设置 > 帮助改进** 上传对应时间范围的诊断，并保留反馈 ID。
