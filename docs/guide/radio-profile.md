# 电台 Profile 与音频

一个 Profile 就是一套可以切换的“物理站台接线”：它把电台连接方式和 RX/TX 音频设备保存在一起。家里 IC-705 的 WLAN、机房里的 rigctld、便携时使用的 USB 声卡，应该分别建成不同 Profile。

## 四个容易混淆的对象

| 对象 | 保存什么 | 不保存什么 | 常见例子 |
| --- | --- | --- | --- |
| **电台 Profile** | CAT/网络连接、PTT 方法、音频输入输出、发射补偿、数字模式电台模式等 | 操作员呼号、登录权限 | “IC-705 WLAN”“FT-991A USB”“纯监听” |
| **电台信息** | 站台呼号、名称、QTH、Maidenhead 格点、简介 | CAT 账号、串口、通联流程 | 对外展示的远程站台资料 |
| **操作员** | 实际发射呼号、网格、音频偏移、发射周期、并行通联上限、通联机制设置 | 物理电台密码和声卡 | 同一站台上的不同呼号或操作席位 |
| **登录用户** | 查看者/操作员/管理员权限，以及能控制哪些操作员 | 无线电呼号本身 | 给远程使用者的令牌或账号 |

一个人可以用管理员账号管理多个操作员；一个操作员也可以在不同 Profile 上工作。不要用 Profile 名称代替呼号，也不要把 ICOM 密码写进站台简介。

## 打开和管理 Profile

在主界面左上电台栏：

- 点击齿轮按钮 **电台配置**，打开 **电台配置 Profile**；
- 点击 **新建电台配置**，建立另一套站台；
- 选中已有 Profile 后点击铅笔按钮编辑；
- 选中非当前 Profile，点击 **应用**完成切换并连接；
- 选中当前 Profile，点击 **重新连接电台**重新建立会话；
- 当前正在使用的 Profile 不能删除。

创建和编辑 Profile 需要管理员权限。远程操作员可以使用管理员已经分配的站台能力，但不能看到或修改被保护的电台凭据。

::: warning 切换前先停止发射
切换 Profile 会更换电台和音频运行环境。先停止 FT8 发射、语音 PTT、单音调谐和所有实验模式发射，再执行切换。切换后重新确认电台名称、频率和 RX 状态。
:::

## Profile 中的电台部分

### Hamlib 直连电台

先选择 **电台型号**。界面会根据 Hamlib backend 自动要求一种端点：

- **串口**：从枚举列表选择实际设备，必要时手动输入路径；
- **服务器地址**：填写主机或 `host:port`；
- **设备路径**：填写 backend 要求的系统设备标识。

大多数电台先保留 backend 默认参数。只有电台说明书明确要求时，再改波特率、数据位、停止位、校验、握手、超时和重试。每次大改后都重新执行 **测试连接** 与 **测试 PTT**。

### Rigctld 服务器

填写 rigctld 的 **主机地址**和**端口**。Profile 保存的是“TX-5DR 去哪里找 rigctld”，物理电台型号和串口则由 rigctld 自己管理。

音频不会自动经过 rigctld。仍需在同一个 Profile 中选择 TX-5DR 服务端可见的输入和输出声卡。

### ICOM WLAN

填写 IP、端口、用户名和密码。连接成功后，音频设备通常保持为 **ICOM WLAN**，由电台网络会话同时承担 RX 与 TX 音频。

只有在确实采用其他音频路由时才改默认设备。即使 Profile 选择了 WLAN 音频，电台本机的网络遥控、DATA/MOD 输入和允许发射设置仍需按型号说明书配置。

### TCI / SunSDR

填写 TCI 主机、端口、接收机、TRX 和 VFO。优先使用 **自动**方言；只有已经知道服务端实现时才固定 ExpertSDR、Thetis 或 AetherSDR 方言。

启用 **TCI 音频**后，输入和输出默认使用 **TCI Audio**。本机 ExpertSDR 常见地址为 `127.0.0.1:40001`，但 TX-5DR 服务端在另一台设备上时，`127.0.0.1` 指向的是服务端自己，必须改成实际可访问的 TCI 主机地址。

### 纯监听

纯监听只保留音频输入，不建立 CAT/PTT 会话，适合 FT8 接收。它不能控制频率、读取电台数值表或发射。

## PTT 方法怎么选

Hamlib 直连和 Rigctld Profile 可以选择：

| 方法 | 使用场景 | 验证方式 |
| --- | --- | --- |
| **CAT 命令（推荐）** | 多数现代电台 | 配置页的 **测试 PTT** |
| **VOX 声控** | SignaLink 等由音频触发的接口 | 先低功率送短音，确认起控和释放延时；界面不会提供 PTT 测试 |
| **DTR 引脚** | 老式接口或外部切换电路 | 选择独立 PTT 串口后执行 **测试 PTT** |
| **RTS 引脚** | 老式接口或外部切换电路 | 选择独立 PTT 串口后执行 **测试 PTT** |

DTR/RTS 的 **PTT 串口**留空时会尝试复用 CAT 串口；如果接口使用另一端口，应明确选择它。不要把实验性的 CW 电键端口和 PTT 端口凭名称猜成同一个设备。

ICOM WLAN 和 TCI 的 PTT 由各自协议处理，不显示 CAT/VOX/DTR/RTS 选择。

## FT8 的电台模式不是软件模式

Profile 中的 **FT8/FT4 电台模式**决定切到数字频率时是否同时向电台写入：

- **不设置电台模式**：只改频率，不碰电台当前模式；
- **USB（上边带）**：写入普通 USB；
- **USB-DATA（上边带数据）**：请求 Hamlib 的数据模式意图。

FT8 是 TX-5DR 中的正式工作模式；FT4 当前是实验功能。USB/USB-DATA 是电台的 CAT 模式，不代表电台已经把 TX 音频源切到 USB、ACC、LAN 或 WLAN。不同厂商对 DATA MOD 的实现不同，第一次发射前仍要在电台菜单手动核对输入来源。

## Profile 中的音频部分

### 音频设备属于服务端

桌面版中，服务端和网页通常在同一台电脑，所以设备列表看起来就是本机声卡。Linux/Docker 服务器版中，Profile 列出的是**服务器所能访问的音频设备**，不是远程浏览器所在电脑的麦克风和扬声器。

因此远程网页可以完全摆脱远程桌面，但物理信号仍要通过以下任一方式到达服务端：

- 连接在服务器上的 USB/PCIe 声卡；
- ICOM WLAN 网络音频；
- TCI Audio 网络音频；
- 已配置的 OpenWebRX 接收音频；
- 独立 Android 运行形态提供的对应音频链路。

浏览器的语音麦克风使用实时音频链路，不会自动变成 Profile 的 FT8 RX 声卡。

### 输入、输出和声道

- **音频输入设备**：电台到 TX-5DR，用于 FT8 接收和解码；
- **音频输出设备**：TX-5DR 到电台，用于 FT8 发射音频；
- **输入/输出采样率**：优先采用设备标记为适合的值；网络虚拟设备会固定所需参数；
- **输出格式**：保持默认，除非已确认声卡 backend 需要另一格式；
- **输出声道**：接口只接左或右声道时要明确选择，避免看似有播放却没有调制。

部分已知 USB 电台会自动匹配设备和采样率，但自动匹配不是收发验收。设备暂时离线时，TX-5DR 会保留已保存的设备而不是悄悄切到另一个声卡；设备恢复后会继续尝试连接。

### 每套 Profile 都要单独校准发射增益

发射音量增益会按 Profile 区分，并按模式类别与波段记忆。换到另一台电台、另一块声卡或 TCI 后，不应沿用上一套站台的安全结论。

每个新 Profile 都从低增益、低 RF 功率开始，使用[搭好第一套站台](./first-steps)中的短时单音步骤重新检查 Power、SWR 和 ALC。

## 发射时序补偿与虚拟频差

**发射时序补偿**用于抵消串口、网络和电台处理延迟。正值代表更早开始，负值代表更晚开始。先保持 0 ms，只有从实际发射时序统计或对方接收证据确认偏差后再调整；过大的补偿会压缩自动回复的决策时间。

**虚拟频差**只作用于 FT8 和实验性的 FT4。它在发射时调整电台频率与音频载波，使实际 RF 位置不变、音频尽量停留在电台较有效的区域。普通站台先保持关闭；确认电台在高低音频处明显掉功率后再启用。

## 推荐的 Profile 命名

名称应让远程用户在切换前就知道会连接什么，例如：

- `IC-705 WLAN · 阳台天线`
- `FT-991A USB · HF`
- `SunSDR2 DX · TCI RX0`
- `OpenWebRX · 20m 纯监听`

不要只写“默认”“电台 1”。描述中可以补充天线、最大允许功率、频段限制和特殊 PTT 接线，但不要写密码或访问令牌。
