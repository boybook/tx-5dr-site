# 电台兼容性与连接方式

TX-5DR 不把兼容性限制在少数指定型号上。它既能通过 Hamlib 接入传统 CAT 电台，也为 ICOM WLAN 和 TCI 提供控制、PTT 与网络音频的一体化连接；只想接收时，还可以完全不连接 CAT。

当前项目随附的 Hamlib 运行时可枚举 **311 个机型条目、72 个厂商名称**。这个数字表示 Hamlib 中存在对应 backend，不代表 TX-5DR 团队逐台做过实机认证，也不保证每一项控制、数值表和音频能力都可用。

## 选择连接方式

| 连接方式 | 适合什么站台 | CAT 与 PTT | RX/TX 音频 | 需要留意 |
| --- | --- | --- | --- | --- |
| **Hamlib 直连电台** | USB CAT、串口 CAT，以及 Hamlib backend 要求设备路径或网络地址的电台 | TX-5DR 直接控制；可选 CAT、VOX、DTR、RTS | 通常另选服务端声卡 | 型号和端点必须选对；同一串口不要再被 WSJT-X/JTDX 占用 |
| **Rigctld 服务器** | 已经用 rigctld 管理电台，希望 TX-5DR 作为客户端接入 | 由现有 rigctld 转发 | 另选服务端声卡 | 填 rigctld 主机和端口；可用能力取决于远端电台和 rigctld |
| **ICOM WLAN** | 具备 ICOM 网络遥控能力、希望不接 USB CAT/声卡 | 网络控制与 PTT | 使用 **ICOM WLAN** 虚拟音频设备 | 不是所有带 Wi-Fi 的 ICOM 都具备相同协议能力；账号、固件和电台网络设置必须正确 |
| **TCI / SunSDR** | SunSDR + ExpertSDR，以及兼容 TCI 的 Thetis/AetherSDR 环境 | TCI 控制与 PTT | 可使用 **TCI Audio** 双向网络音频 | 核对 TCI 服务、端口、接收机/TRX/VFO；兼容方言的能力并不完全相同 |
| **纯监听** | 只做 FT8 接收、暂时不控制电台，或先排查音频链路 | 无 | 只配置 RX 输入 | 不提供改频、PTT、发射和电台参数控制 |

“Hamlib 直连电台”不一定只接受串口。选择型号后，界面会根据该 backend 改为 **串口**、**服务器地址**或**设备路径**，并显示它真正需要的连接参数。

::: tip 从 WSJT-X/JTDX 迁移时
如果 WSJT-X/JTDX 正在直接打开 CAT 串口，TX-5DR 通常无法再打开同一端口。关闭原软件的电台控制，或把物理电台交给一个 rigctld，再让需要的客户端通过网络访问。不要让两个程序分别抢占同一个 USB 串口和 TX 声卡。
:::

## 各连接方式提供的能力

### Hamlib 直连

在 **电台配置 → Hamlib 直连电台** 中搜索厂商和型号。TX-5DR 会读取 Hamlib 提供的端口类型、连接参数和能力声明，并在连接后继续探测实际可读写的项目。

适合这类情况：

- 电台通过 USB 虚拟串口或传统 RS-232 CAT 连接；
- 电台使用 Hamlib 自带的网络 backend，但不希望另行启动 rigctld；
- 需要 CAT 改频、模式意图、PTT、Split 或电台数值表/参数控制；
- RX/TX 音频通过 USB Audio、SignaLink 或其他声卡接口进入 TX-5DR 服务端。

Hamlib 能列出型号，只代表“有可尝试的驱动”。电台固件、USB 驱动、线材、菜单设置和 Hamlib 版本都可能影响结果。某些 backend 只可靠提供频率和 PTT，某些则能继续提供 Power、SWR、ALC、天调、频谱或更多参数。

### Rigctld 服务器

选择 **Rigctld 服务器** 后，填写已经运行的 rigctld 地址。这种方式适合已有 Linux 电台主机、局域网 CAT 服务，或需要集中占用物理串口的站台。

注意区分两个方向：

- Profile 中的 **Rigctld 服务器**：TX-5DR 是客户端，连接一个外部 rigctld；
- 设置中的 **Rigctld 桥接**：TX-5DR 向其他软件提供兼容入口。

它们不是同一个开关。初次搭建只需要选择符合实际拓扑的一种，避免形成环路。

### ICOM WLAN

ICOM WLAN 把电台控制、PTT、RX 音频和 TX 音频放在同一网络会话中。配置成功后，Profile 的输入和输出通常都使用 **ICOM WLAN**，无需再给 TX-5DR 接 USB 声卡，因此很适合机房、阳台站台或与操作位置分离的电台。

使用前确认：

- 电台型号和固件确实支持所需的 ICOM 网络遥控协议；
- 电台已开启 WLAN/网络遥控功能；
- TX-5DR 服务端可以直接访问电台 IP 和端口；
- 用户名、密码正确，且没有被其他遥控客户端占用；
- 第一次 PTT 前已在电台菜单核对网络音频和 DATA 输入来源。

### TCI / SunSDR

TCI 面向 ExpertSDR/SunSDR，并提供 ExpertSDR、Thetis、AetherSDR 等方言选择。默认自动识别；40001 严格握手失败时，可以探测常见的 50001 端口。

开启 **TCI 音频** 后，Profile 中会出现 **TCI Audio** 输入和输出。这样 CAT、PTT、频率、部分电台状态以及 RX/TX 音频都可以经网络完成。具体数值表、频谱和参数控制仍取决于当前 TCI 服务实际发送了什么，不能把某个方言支持的功能推断到所有 TCI 软件。

### 纯监听

纯监听不会向电台发送任何控制或 PTT 命令。它适合先验证 FT8 接收声卡、临时接收机或只读站点。

如果输入来自 OpenWebRX，应先配置对应的 OpenWebRX 站点和接收 Profile；如果来自本地声卡，就在 Profile 中直接选择输入设备。纯监听模式不能靠后来打开“发射”按钮变成可发射配置，需要新建或切换到有电台控制的 Profile。

## 如何理解“支持”

兼容列表或问题反馈应使用以下等级，避免把上游枚举当成实机结论：

| 等级 | 含义 | 可以据此期待什么 |
| --- | --- | --- |
| **项目实机验证** | 有明确型号、固件、连接方式和版本的完整收发记录 | 记录中列出的能力在相同条件下应可复现 |
| **用户报告可用** | 用户在真实站台报告成功，并能说明关键配置 | 可作为较强参考，但仍受固件、系统和接线差异影响 |
| **Hamlib 上游枚举** | 当前 Hamlib 返回该厂商/型号 | 可以在下拉列表选择并测试，不代表 TX-5DR 已认证 |
| **尚未验证** | 没有足够的真实站台证据 | 需要按下方清单逐项验收，不应直接启用自动发射 |

“电台型号可选”“测试连接成功”“完整可用”是三个不同结论。测试连接成功后，仍要逐项确认音频、PTT、频率写入和发射遥测。

## 一台电台的完整验收清单

记录型号兼容性时，至少写清 TX-5DR 版本、电台固件、操作系统和连接方式，并依次检查：

1. **连接**：连续连接和重连正常，没有其他程序抢占端口；
2. **频率读取**：转动 VFO 后网页频率能跟随；
3. **频率写入**：从 TX-5DR 切换到一个合法预设，电台准确跟随；
4. **模式**：FT8 正式功能使用的 USB/USB-DATA 意图符合电台菜单；FT4 当前属于实验功能；
5. **PTT**：0.5 秒测试能够可靠进入 TX 并回到 RX；
6. **RX 音频**：瀑布和 FT8 解码稳定，没有削顶、断续或错误声道；
7. **TX 音频**：低功率单音能产生正常 Power，SWR 和 ALC 在安全范围；
8. **数值表**：逐项记录 Level、Power、SWR、ALC 哪些可用；
9. **电台控制**：记录天调、RF、音频、操作、系统五组中实际出现且可写的项目；
10. **长时间运行**：观察重连、频率同步和 PTT 释放，不以一次成功代替稳定性验证。

详细的验收顺序见[搭好第一套站台](./first-steps)，控制项目的含义见[数值表与电台控制](./radio-controls)。
