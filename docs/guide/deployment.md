# 长期运行、远程访问与升级

TX-5DR 可以让运行主机留在电台旁，操作员只用浏览器完成频率控制、解码、通联和日志操作。这与远程桌面不同：浏览器接收的是 TX-5DR 自己的界面和实时状态，不需要传输整个操作系统桌面，也不会依赖一条持续存在的桌面会话。

长期运行的关键不是把网页端口直接开放到互联网，而是同时处理好访问范围、身份验证、HTTPS、数据备份、电台安全和更新验证。

## 选择运行主机

| 运行形态 | 长期值守时的特点 | 服务何时停止 |
| --- | --- | --- |
| 桌面版 | 最容易从本机开始，也能共享给浏览器 | 退出应用、用户会话结束或电脑休眠 |
| Linux 服务器 | 无需图形桌面，可由 systemd 开机启动 | 停止服务、关机或故障 |
| Docker | 便于纳入现有容器监控和备份 | 容器停止、宿主机关机或故障 |
| Android | 便携、低功耗，内置 WebView 与热点/LAN 入口 | 停止服务、系统杀后台或设备断电 |

桌面版适合先验证系统。真正长期无人值守时，Linux 服务器或 Docker 的生命周期更清晰；移动和便携场景可使用 Android。

## 从本地逐步开放访问

### 1. 纯本地使用

先在电台旁完成 CAT、PTT、音频和低功率发射测试。桌面版可以在“系统设置 > 访问范围”选择“纯本地使用”，此时只有本机可以连接。

### 2. 局域网共享

选择“局域网共享”，使用界面或平台状态页显示的 LAN 地址访问。所有使用者都应使用自己的操作员身份或令牌；不要多人共用管理员令牌。

### 3. 私有网络远程访问

这是跨地点使用的推荐方式。Tailscale、ZeroTier、WireGuard 等私有组网可以让远端设备像位于同一局域网中一样访问，同时避免直接暴露 TX-5DR 端口。

### 4. 域名或反向代理

在“系统设置 > 访问范围”选择“正式开放部署”，并添加浏览器实际使用的完整地址，例如：

```text
https://radio.example.com
https://radio.example.com:8443
```

Origin 只包含协议、主机和端口，不能包含路径、查询参数、凭据或末尾斜杠。反向代理、FRP 或 Tunnel 必须正确转发 HTTP 和 WebSocket。远程监听与语音还可能需要额外网络配置，见[远程监听与语音链路](./realtime-audio)。

## 公网安全底线

- 首选私有组网，不要直接把 TX-5DR Web、rigctld 或电台控制端口暴露到公网。
- 使用 HTTPS 保护登录令牌和控制数据；HTTP 虽可访问，但链路内容未加密。
- 为每位使用者分配满足其职责的最低权限。观察者不应获得发射控制。
- 不需要公开查看时，关闭“允许无需登录只读查看”。
- 反向代理、防火墙和 VPN 不能替代 TX-5DR 自身的登录与访问范围设置。
- 保留本地停止发射和断开 PTT 的办法。无人值守前先用低功率验证超时、断线和重启后的状态。

## 公网地址被拒绝时

如果页面显示 `origin_not_allowed`，不要删除整个认证配置。通过本地浏览器或 SSH，把当前浏览器 Origin 加入“允许访问的网页地址”。

Linux 服务器无法进入界面时，可以离线修改：

```bash
sudo tx5dr stop
sudoedit /var/lib/tx5dr/config/auth.json
```

在已有的 `remoteAccess` 对象中只调整以下字段，保留其他连接数和超时参数：

```json
"preset": "public",
"allowedOrigins": ["https://radio.example.com"]
```

验证 JSON 后再启动：

```bash
sudo node -e "JSON.parse(require('fs').readFileSync('/var/lib/tx5dr/config/auth.json', 'utf8')); console.log('auth.json OK')"
sudo tx5dr start
```

如果 `/etc/tx5dr/config.env` 修改了 `TX5DR_CONFIG_DIR`，应编辑对应目录中的 `auth.json`。Docker 默认对应宿主机的 `./data/config/auth.json`，修改前先停止容器，完成后再启动。

## 备份什么

| 形态 | 建议备份 |
| --- | --- |
| 桌面版 | 日志本导出、配置、插件与系统显示的数据目录 |
| Linux 服务器 | 整个 `/var/lib/tx5dr`；自定义证书还包括 `/etc/tx5dr/ssl` |
| Docker | Compose 文件和整个宿主机 `./data` 目录 |
| Android | “诊断与设置 > 数据目录”中的用户数据、日志、插件和插件数据 |

运行环境和安装包可以重新下载，通联日志、身份、Profile、插件设置和令牌则属于用户数据。备份应保存到运行主机之外，并定期做一次实际恢复演练。

复制运行中的数据前，先结束发射并正常停止 TX-5DR，可避免刚写入的日志或配置只复制了一部分。

## 更新流程

### 每次更新前

1. 结束所有通联并确认 PTT 已释放。
2. 记录当前版本和关键 Profile 状态。
3. 备份对应平台的数据目录。
4. 确认可以在本地接触电台，或至少拥有独立的远程断电/停发手段。

### 执行更新

| 形态 | 更新方式 |
| --- | --- |
| 桌面版 | 在“设置 > 关于”检查并安装更新；不支持自动安装时按提示手动下载 |
| Linux 服务器 | `tx5dr update` |
| Docker | `docker compose pull && docker compose up -d` |
| Android | 安装新的 APK；在“诊断与设置 > 安装/更新”更新 TX-5DR 引擎 |

Android APK 与 TX-5DR 引擎是两个更新通道。只更新其中一个，不代表另一部分也已更新。

### 更新后验证

- 页面能打开，版本符合预期
- 电台重新连接，频率、模式和主要能力正确显示
- 接收音频有电平，数字模式能正常解码
- 以低功率测试 PTT、发射音频和停止发射
- 远程浏览器、用户权限和 HTTPS 入口仍然正常
- 日志本、Profile、插件和令牌没有丢失

不要把“安装包下载成功”“镜像拉取成功”当作运行验证。真正完成升级的标志是新版本已经运行，并且电台、音频、登录和发射保护都通过检查。

## 出现问题时先收集什么

| 形态 | 首要入口 |
| --- | --- |
| 桌面版 | 系统设置中的状态与诊断信息 |
| Linux 服务器 | `tx5dr status`、`tx5dr doctor`、`tx5dr logs --all` |
| Docker | `docker compose ps`、`docker compose logs --tail=200 tx5dr` |
| Android | 状态页的“诊断”，以及 Server、Web、Bridge 三组运行日志 |

记录发生时间、正在使用的 Profile、电台连接方式、浏览器地址和可见错误。分享日志前移除令牌、密码、私有证书和不希望公开的个人信息。
