# 操作员、用户与远程访问

TX-5DR 的服务端可以留在电台旁，操作员从其他电脑、平板或手机直接打开网页。这不是把电台电脑的桌面画面传出去：频谱、解码、控制和日志本来就是 Web 界面，因此不需要保持远程桌面会话，也不会受远程桌面分辨率、窗口焦点或音频重定向影响。

## 与远程桌面的区别

| 远程桌面方式 | TX-5DR 浏览器方式 |
| --- | --- |
| 远程传输整块桌面画面 | 浏览器只接收 TX-5DR 的界面和数据 |
| 操作依赖主机桌面会话 | Linux 无头主机也能运行 |
| 手机和平板操作通常拥挤 | 同一 Web UI 会适配不同屏幕 |
| 多人容易争抢鼠标和焦点 | 用户权限和操作员分别管理 |
| 远程音频依赖桌面软件重定向 | TX-5DR 提供自己的监听和麦克风链路 |

服务器版、Docker 和 Android 都适合让运行设备长期靠近电台。桌面版也可以向局域网提供同一套浏览器入口。

## Profile、台站、操作员和登录用户

### 电台 Profile

保存电台连接、PTT 和音频设备。切换 Profile 等于切换一套硬件连接方案。

### 电台信息

描述共享站台，例如站名、站台呼号、QTH、经纬度、天线和说明。它不是某次实际发报使用的操作员身份。

### 操作员

保存实际参与通联的呼号、Grid、通联机制和操作员级插件设置。FT8、语音、CW 和 SSTV 日志都会关联到操作员。

### 登录用户

决定浏览器里的人能看什么、能控制哪个操作员，以及能否修改系统。一个登录用户可以被授权操作一个或多个操作员。

![操作员设置页面，显示操作员身份、日志同步和插件设置](/guide/screenshots/original/operator-settings.png)

*操作员保存呼号、Grid、通联能力和操作员级插件设置；登录用户决定谁可以使用这些操作员。*

## 三种角色

| 角色 | 典型用途 | 主要能力 |
| --- | --- | --- |
| 观察者 | 公开接收页、值守查看 | 查看频谱、解码、状态和允许公开的数据 |
| 操作员 | 实际通联 | 控制被授权的操作员和允许的电台功能 |
| 管理员 | 台站所有者 | 管理 Profile、用户、远程访问、插件和系统设置 |

角色只是默认能力级别。管理员创建用户时还可以限制操作员、频段、频率范围和具体权限。

## 创建给其他人的访问方式

进入 **设置 > 用户管理**：

1. 新建用户并填写可识别的名称。
2. 选择观察者、操作员或管理员角色。
3. 如果是操作员，勾选允许使用的操作员呼号。
4. 根据需要设置可创建的操作员数量和有效期。
5. 保持默认权限，或进一步限制频段和操作能力。
6. 创建后复制访问令牌或分享二维码。

也可以为用户配置用户名和密码。令牌或密码都应当单独分配，不要多人长期共用管理员令牌。

需要收回访问时，应撤销或重新生成对应用户的令牌，而不是仅删除浏览器书签。

### 用户自行设置用户名和密码

管理员创建用户时可以允许其自行管理登录方式。获得允许后，用户可点击主界面右上角的当前身份，再打开 **账号安全**：

1. 首次设置时填写至少 3 位的用户名和至少 8 位的密码。
2. 已经配置后，只改用户名可以把新密码留空。
3. 保存后退出一次，使用新用户名和密码验证登录。

用户名密码仍绑定到原来的用户令牌和权限，不会创建新的管理员。界面提示“管理员未允许自行设置”时，应由管理员在用户管理中开启该权限或直接代为配置。

## 选择访问范围

进入 **设置 > 系统设置 > 访问范围**，选择与网络拓扑一致的预设。

![访问范围设置，标出局域网与正式部署、公开只读开关和浏览器地址](/guide/screenshots/annotated/remote-access.png)

*局域网共享会显示可访问地址；正式开放部署还需要配置浏览器实际使用的 Origin。*

### 仅本机

只允许当前设备访问。适合单机桌面使用和初次配置。

### 局域网

允许同一可信 LAN 或 Android 热点中的设备访问：

1. 选择 **局域网**。
2. 保存后查看界面显示的 LAN 地址。
3. 在另一台设备的浏览器中打开该地址。
4. 使用为该用户创建的令牌或账号登录。

### 公网

公网模式要求明确配置允许访问的完整 Web 地址，也就是浏览器地址栏中的协议、主机名和非默认端口，例如：

```text
https://radio.example.com
https://radio.example.com:8443
```

地址不能包含路径、查询参数或末尾斜杠。只把网页转发到公网但不加入允许地址，会被 Origin 检查拒绝。

::: danger 不要直接裸露到不可信网络
优先使用受控 VPN、可信反向代理和 HTTPS。若关闭 Rigctld 只读模式或授予发射权限，能够连接端口的客户端可能实际控制电台。
:::

## 公开观察

启用 **允许公开查看** 后，未登录访问者可以作为只读观察者进入。公开观察者不能发射或修改电台，但你仍应检查公开页面会展示哪些台站和解码信息。

公开查看不等于公开操作。需要控制电台的人仍应使用单独账号，并只获得必要权限。

## 多操作员使用同一部电台

多个浏览器用户和多个电台操作员是两件事：

- 浏览器用户决定谁有权限操作
- 电台操作员决定以哪个呼号和策略通联
- Profile 决定所有人当前共享哪一套物理电台和音频设备

FT8 可以为多个操作员保留独立状态，某些策略也支持并行通联；实际能否同时发射多路信号，还受标准频率限制、电台能力、当前策略和防冲突逻辑约束。初次部署应先使用单操作员、单路通联，再逐步开放并行能力。

语音、实验性的 CW 和 SSTV 共用物理发射机；实验性的 FAX 当前仅接收。界面出现“被其他操作占用”时，不要绕过互斥或反复点击 PTT。

## 远程监听和发射

网页能打开只代表控制通道可用。远程监听和浏览器麦克风还需要音频链路：

- 只看 FT8 解码通常不需要浏览器麦克风
- 在浏览器中监听电台需要启动音频监听
- 语音 PTT 需要 HTTPS 或 `localhost` 才能稳定获得麦克风权限
- 公网低延迟音频可能还需要额外 UDP 映射

完整配置见 [远程监听与语音链路](./realtime-audio)。

## 远程站最低安全检查

- 管理员令牌没有发给普通操作员
- 每个人使用独立用户，权限只覆盖必要操作员和频段
- 公网地址使用 HTTPS，并已加入允许地址
- Rigctld 默认保持只读，除非确实需要外部软件写入
- 能从远端立即停止发射，并有现场断电或人工处置方案
- 更新、重启和网络中断不会让 PTT 保持在发射状态
