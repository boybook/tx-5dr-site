# 外部集成

TX-5DR 可以把远端 SDR、传统电台软件、PSK Reporter 和外部日志服务接入同一站台。集成前先明确数据方向：是让 TX-5DR 使用外部接收机，还是让其他软件读取或控制 TX-5DR 当前连接的电台。

## OpenWebRX 辅助接收

OpenWebRX 可以作为独立接收链路。常见用途包括：

- 使用底噪更低或位置更好的远端 SDR 解码
- 本地电台发射时继续从远端接收
- 在本地电台发射周期仍从远端接收，持续获得数字模式解码
- 在使用前试听并选择合适的 SDR Profile

进入 **设置 > OpenWebRX**：

1. 添加站点名称和 WebSocket 地址。
2. 点击 **测试连接**，确认能读取服务器版本和 Profile。
3. 选择一个覆盖目标频率的 Profile。
4. 使用试听面板检查频率、调制方式和音频。
5. 保存后回到主界面选择 OpenWebRX 频谱或接收源。

远端站点可能限制并发、调谐范围或切换频率的速度。未经站点所有者允许，不要把公共 SDR 当作长期独占接收机。

## 向 WSJT-X、JTDX、N1MM 或 fldigi 提供电台控制

TX-5DR 可以开启一个 Hamlib NET rigctl 兼容端口，让其他软件读取当前电台状态。进入 **设置 > Rigctld 桥接**：

1. 启用 Rigctld 桥接。
2. 本机使用时监听 `127.0.0.1`；需要 LAN 客户端时再选择 LAN 地址或全部接口。
3. 默认端口为 `4532`。
4. 首次使用保持 **只读模式**。
5. 保存后在客户端软件中选择 `Hamlib NET rigctl`，服务器填写 `主机IP:4532`。

只读模式允许外部软件读取频率、模式和 PTT 状态，但拒绝切频、改模式和发射。只有确实需要 N1MM spot 自动切台、外部语音键盘或其他写入能力时才关闭只读。

::: danger Rigctld 没有浏览器账号保护
关闭只读后，任何能连接该 TCP 端口的客户端都可能切频、改模式、控制 Split 或 PTT。只在可信网络开放，并在使用结束后恢复只读。
:::

Docker 使用 LAN Rigctld 时还需要映射对应 TCP 端口。公网环境不应直接暴露 Rigctld。

## WSJT-X 兼容 UDP

内置 **QSO UDP Broadcast** 插件可以向第三方软件发送 WSJT-X 兼容数据：

- 状态与频率
- 解码消息
- QSO Logged
- Logged ADIF

进入 **设置 > 插件**，找到该插件并为操作员配置 UDP 目标。默认目标通常是 `127.0.0.1:2237`。

插件还可以选择接受 Reply、Halt Tx、Free Text 等远程请求。这些选项默认关闭；开启前应确认接收端可信，并理解它将获得怎样的发射控制能力。

## PSK Reporter

进入 **设置 > 系统设置 > PSK Reporter**：

1. 确认接收台呼号和 Grid。
2. 留空时，系统会尝试使用第一个操作员的信息。
3. 启用上报并检查待发送数量和最近上报时间。

PSK Reporter 上报的是接收到的数字信号，不是通联日志同步。错误的接收 Grid 会影响地图位置，开始长期上报前应先验证。

## 日志服务

WaveLog、QRZ.com、LoTW 和 Club Log 通过日志同步插件接入。操作步骤和数据边界见 [通联日志](./logbook#同步外部服务)。

## 如何避免两个程序争抢电台

- 同一物理串口不要同时由 TX-5DR 和 WSJT-X/JTDX 直接打开
- 如果 TX-5DR 直接连接电台，让其他软件通过 TX-5DR 的 Rigctld 桥接读取
- 如果已有独立 rigctld 管理电台，让 TX-5DR 选择 **Rigctld 服务器** 连接方式
- 先决定谁拥有 PTT，再启用外部写入
- 频率或模式反复跳变时，先关闭所有外部写入客户端再排查
